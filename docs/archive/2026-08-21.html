🧠 Data Science Topic of the Day

🎓 SHAP (SHapley Additive exPlanations)

Turning black-box model predictions into plain-English reasons — every prediction, every time.

What It Is

SHAP is a game-theory-based method for explaining the output of any machine learning model. Rooted in Shapley values from cooperative game theory, it assigns each input feature a contribution score for a specific prediction — answering not just 'what did the model predict?' but 'why did it predict that?' Unlike older feature importance methods (e.g. mean decrease in impurity from Random Forests), SHAP values are locally faithful (they explain individual predictions, not just global averages), consistent (a feature that matters more always gets a higher SHAP value), and model-agnostic — they work on XGBoost, neural nets, linear models, and everything in between.

How It Works

1. SHAP treats each feature as a 'player' in a coalition game. The target is the model's output. The Shapley value for a feature is the average marginal contribution that feature makes across every possible ordering of features being added to the prediction. 2. For tree-based models (XGBoost, Random Forests), TreeSHAP computes exact Shapley values in polynomial time — no sampling needed, making it practical at scale. 3. For deep learning, DeepSHAP and GradientSHAP use backpropagation to approximate values efficiently. 4. KernelSHAP is the fully model-agnostic fallback — slower, but works on any model. 5. The outputs: (a) Local explanation — a waterfall chart showing which features pushed a single prediction up or down from the baseline. (b) Global explanation — a beeswarm or bar plot aggregating SHAP values across the dataset to show overall feature importance. (c) Dependence plots — show how one feature's SHAP value changes across its range, revealing non-linearities and interactions. Key property: SHAP values are additive. Sum all feature SHAP values + baseline expected prediction = the model's actual output for that row. This makes them auditable and mathematically rigorous.

When To Use

1. Regulatory / compliance contexts where model decisions must be explainable (credit risk, KYC, supplier risk scoring). 2. Debugging model behaviour — when a model performs well on average but makes puzzling individual predictions, SHAP surfaces the culprit features. 3. Feature engineering feedback loops — identify low-value features dragging model complexity without adding predictive lift. 4. Sales / customer-facing explainability — 'Here is why your Paydex score changed this month.' 5. Detecting data leakage — if a feature dominates SHAP globally in a suspicious way, it often signals leakage. 6. Monitoring model drift — track the distribution of SHAP values for key features over time; a shift in SHAP distributions before accuracy degrades is an early warning signal.
