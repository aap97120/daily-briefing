🧠 Data Science Topic of the Day

🎓 Random Forests

Wisdom of crowds, applied to decision trees — robust, interpretable, and remarkably hard to fool.

What It Is

Random Forests are an ensemble learning method that builds a large number of decision trees during training and outputs the majority vote (classification) or average prediction (regression) across all trees. The core insight is elegant: individual decision trees overfit badly, but if you build hundreds of them on random subsets of data and random subsets of features, their errors are uncorrelated — so they cancel out when averaged. The result is a model that generalises far better than any single tree, handles missing data gracefully, works on tabular data without feature scaling, and naturally produces feature importance scores. It was formalised by Leo Breiman in 2001 and remains one of the most battle-tested algorithms in production data science — especially on structured, tabular business data where it frequently matches or beats deep learning.

How It Works

1. BOOTSTRAP SAMPLING (Bagging): For each of N trees, draw a random sample of the training rows *with replacement* (a 'bootstrap' sample). Each tree sees roughly 63% of the original rows; the remaining ~37% — the 'out-of-bag' (OOB) rows — act as a free validation set. 2. RANDOM FEATURE SUBSETS: At every node split within a tree, only a random subset of features (typically √p for classification, p/3 for regression, where p = total features) is considered as split candidates. This is the key differentiator from plain bagging — it deliberately decorrelates the trees so dominant features don't dominate every tree. 3. GROW TREES FULLY (or near-fully): Unlike pruned single trees, RF trees are typically grown deep. Bias is low per tree; variance is tamed by averaging. 4. AGGREGATE PREDICTIONS: For classification, majority vote across all trees. For regression, mean of all tree outputs. Predicted probabilities = fraction of trees voting for each class. 5. OUT-OF-BAG ERROR: Each tree's OOB rows give a near-unbiased generalisation error estimate for free — no separate validation set needed. 6. FEATURE IMPORTANCE: Two flavours — (a) Mean Decrease in Impurity (MDI): average reduction in Gini/entropy a feature causes across all splits in all trees; fast but biased toward high-cardinality features. (b) Permutation Importance: shuffle a feature's values on OOB data and measure accuracy drop; slower but unbiased. Both give a ranked list of which features actually drive predictions. KEY HYPERPARAMETERS: - n_estimators: number of trees (more = better up to diminishing returns; 300–1000 is typical) - max_features: size of random feature subset per split - max_depth / min_samples_leaf: controls individual tree complexity - class_weight: handles class imbalance without resampling

When To Use

USE IT WHEN: • Your data is tabular/structured (not raw images or free text) — RF is almost always a strong baseline here. • You need feature importance natively, without post-hoc tools like SHAP (though SHAP works on RF too). • Interpretability of individual predictions matters less than overall model reliability — RF is a 'black box' at the prediction level but transparent at the feature level. • You have missing data or mixed feature types — RF handles both without heavy preprocessing. • You want robustness: RF is very hard to overfit with more trees and rarely catastrophically wrong. • You need a fast, reliable benchmark before investing in XGBoost tuning or deep learning. DO NOT USE IT WHEN: • Data is sequential/temporal and order matters (use RNNs, LSTMs, or time-series models). • Data is unstructured: images, audio, raw text (use CNNs, transformers). • You need fully transparent, auditable logic for a single prediction (use a single decision tree or logistic regression). • Inference latency is critical at the edge — a forest of 500 trees is slower than a linear model. • You need to extrapolate beyond the training data range — RF averages seen leaf values, so it cannot extrapolate.

🎯 Worked Example — D&B Context

PROBLEM: D&B wants to predict which of its 600M+ business records are likely to churn from a data subscription within the next 90 days — the 'Pipeline Risk & Revenue Protection' agent archetype. FEATURES AVAILABLE (all from D&B's proprietary stack): - Paydex score and 12-month trend (improving/deteriorating) - Days since last API query (recency) - Query volume change month-over-month (engagement delta) - Number of DUNS records pulled in last 30 days - Corporate family tree depth (subsidiary count — proxy for complexity/stickiness) - Number of support tickets raised in last quarter - Contract tenure (months) - Industry vertical (SIC code bucket) - Buydex-derived spending signals (proxy for financial health) - Whether the account has an active integration with a partner platform (Salesforce, Microsoft) STEPS: 1. Label historical accounts: churned within 90 days = 1, retained = 0. Class imbalance (~15% churn) — set class_weight='balanced'. 2. Split: 70% train, 15% validation, 15% test. Use OOB error as a sanity check on training. 3. Train RandomForestClassifier (n_estimators=500, max_features='sqrt', max_depth=None, class_weight='balanced'). 4. Tune max_features and min_samples_leaf via 5-fold CV on the training set. 5. Evaluate: AUC-ROC ~0.84, precision-recall AUC ~0.61 (better baseline than logistic regression's 0.72 AUC). FEATURE IMPORTANCE OUTPUT (permutation importance, ranked): 1. Days since last API query — by far the strongest signal 2. Query volume change MoM 3. Paydex 12-month trend 4. Support ticket count 5. Contract tenure 6. Partner platform integration (negative churn correlation — integrated customers stay) BUSINESS OUTPUT: The Pipeline Risk agent scores all active accounts nightly. Accounts in the top decile of churn probability get flagged in Salesforce Agentforce with an AI-generated 'at-risk brief' — pulling in the top contributing features as plain-English reasons ('API usage dropped 60% last month; Paydex deteriorating').
