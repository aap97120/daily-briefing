🧠 Data Science Topic of the Day

🎓 XGBoost & Gradient Boosted Trees

The workhorse that still beats deep learning on structured tabular data — and why it belongs at the heart of D&B's scoring models.

What It Is

XGBoost (Extreme Gradient Boosting) is an ensemble learning algorithm that builds a strong predictive model by sequentially adding shallow decision trees, where each new tree corrects the residual errors left by the previous ones. It is part of the broader 'gradient boosted trees' family (alongside LightGBM and CatBoost). Despite being over a decade old, it consistently wins Kaggle competitions and production deployments on structured/tabular data — exactly the kind of data D&B lives in: firmographics, payment history, trade data, credit attributes. It is not a neural network; it requires no GPU and produces fully interpretable feature importance scores out of the box.

How It Works

1. START WITH A BASE PREDICTION — The model starts with a simple prediction (e.g., the mean of the target variable) and computes residuals (errors) for every observation. 2. FIT A SHALLOW TREE TO THE RESIDUALS — A decision tree is trained not on the raw labels, but on the residuals — it learns 'where did the last model go wrong?' 3. GRADIENT DESCENT IN FUNCTION SPACE — XGBoost frames tree-building as gradient descent: the 'gradient' is the direction that most reduces the loss function (e.g., log-loss for classification, MSE for regression). Each new tree is a step down that gradient. 4. REGULARISATION (THE 'X' IN XGBOOST) — Unlike vanilla gradient boosting, XGBoost adds L1 (Lasso) and L2 (Ridge) regularisation terms directly into the tree-splitting objective. This penalises overly complex trees and prevents overfitting — critical when your training data has noisy financial signals. 5. SHRINKAGE (LEARNING RATE) — Each tree's contribution is scaled by a learning rate (eta, typically 0.01–0.3). Smaller learning rates require more trees but generalise better. 6. COLUMN & ROW SUBSAMPLING — Like Random Forests, XGBoost randomly subsamples features and rows per tree, adding further variance reduction. 7. REPEAT — Steps 2–6 repeat for N rounds (trees). Final prediction = sum of all tree outputs passed through the link function (e.g., sigmoid for binary classification). KEY HYPERPARAMETERS TO TUNE: - n_estimators: number of trees (more = slower but potentially better) - max_depth: tree depth (3–8 typical; deeper = more complex) - eta / learning_rate: step size shrinkage - subsample: fraction of rows per tree - colsample_bytree: fraction of features per tree - min_child_weight: minimum sum of instance weight in a leaf (controls overfitting) - gamma: minimum loss reduction required to make a split FEATURE IMPORTANCE — XGBoost provides three importance metrics: - Weight: how often a feature is used in splits - Gain: average improvement in loss when that feature splits - Cover: average number of observations affected by splits on that feature Gain is generally the most informative for business interpretation.

When To Use

USE XGBOOST WHEN: - Your data is tabular/structured (rows = entities, columns = features) — firmographics, financials, payment records, CRM data - You have a mix of numeric and categorical features with missing values (XGBoost handles missingness natively) - You need fast training without GPU infrastructure - Explainability matters — stakeholders need to understand why a score moved - You are doing classification (churn, default, conversion), regression (deal size, revenue), or ranking (lead prioritisation) - Your dataset is small-to-medium (thousands to low millions of rows) — deep learning needs far more data to justify its complexity DO NOT USE XGBOOST WHEN: - Your input is unstructured (text, images, audio) — use transformers - You need temporal sequence modelling over long windows — use LSTMs or transformers - You have billions of rows and need distributed training at extreme scale — use LightGBM or Spark MLlib - You need uncertainty quantification natively — consider Bayesian approaches or conformal prediction wrappers
