🧠 Data Science Topic of the Day

🎓 XGBoost — Gradient Boosted Trees in Depth

The algorithm that still wins most tabular data competitions — and why it belongs at the heart of D&B's scoring models.

What It Is

XGBoost (eXtreme Gradient Boosting) is an ensemble learning algorithm that builds a sequence of decision trees, where each new tree corrects the residual errors of the combined trees before it. It sits in the 'boosting' family of methods — distinct from Random Forests (which build trees in parallel and average them). XGBoost builds trees serially, each one a small specialist in fixing what the previous ensemble got wrong. It is fast, regularised to resist overfitting, handles missing values natively, and consistently outperforms most alternatives on structured/tabular data. For D&B — whose core commercial value lies in scoring 600M+ business records on credit risk, propensity to buy, and financial stress — XGBoost is not a novelty: it is likely already embedded in production pipelines today.

How It Works

1. INITIALISATION: Start with a simple base prediction (e.g. the mean of the target variable). Compute the residuals — the gap between prediction and reality. 2. FIT A TREE TO RESIDUALS: Train a shallow decision tree to predict those residuals, not the original target. This tree is the 'correction layer.' 3. SHRINK AND ADD: Scale the new tree's output by a learning rate (e.g. 0.1) and add it to the running ensemble. Shrinking prevents any single tree from dominating. 4. REPEAT: Compute new residuals from the updated ensemble and fit the next correction tree. Repeat for N rounds (typically 100–1000). 5. GRADIENT DESCENT IN FUNCTION SPACE: The 'gradient' in gradient boosting refers to the fact that residuals are actually the negative gradient of a loss function (e.g. log-loss for classification, MSE for regression). Each tree steps the ensemble down the loss surface — just like SGD moves neural network weights, boosting moves the prediction function itself. 6. XGBOOST-SPECIFIC ENHANCEMENTS: (a) Second-order gradients (Newton boosting) — uses both gradient and curvature of the loss for smarter tree splits. (b) L1 + L2 regularisation terms on leaf weights — explicitly penalises complexity in the objective function, not as an afterthought. (c) Column subsampling — randomly samples features per tree (like Random Forests), adding diversity and speed. (d) Sparsity-aware split finding — handles missing values by learning the optimal default direction for NaN values during training. (e) Histogram-based approximate splits — bins continuous features into buckets for speed on large datasets. KEY HYPERPARAMETERS TO TUNE: n_estimators (number of trees), max_depth (tree complexity, typically 3–6), learning_rate (shrinkage), subsample (row sampling), colsample_bytree (column sampling), min_child_weight (leaf size floor), gamma (minimum gain to split), reg_alpha / reg_lambda (L1/L2). Standard tuning approach: fix a moderate learning rate (0.05–0.1), tune tree structure parameters via cross-validation, then optionally lower learning rate and increase n_estimators for final polish.

When To Use

USE XGBOOST WHEN: (1) Your data is tabular/structured — XGBoost consistently beats deep learning on rows-and-columns data without massive scale. (2) You need interpretable feature importance — native gain/cover/frequency importance scores, and it integrates directly with SHAP. (3) Training data is in the millions, not billions — it scales well but is not a distributed-first tool (use LightGBM or Spark MLlib's GBT for truly massive data). (4) Missing data is endemic — as it is in business datasets where not every firmographic field is populated for every company. (5) You need a well-calibrated probability output — e.g. P(company defaults in 90 days), P(account expands in next quarter). PREFER OTHER APPROACHES WHEN: Sequential/temporal dependencies dominate (use LSTMs or Transformers); you have unstructured text/image inputs (use deep learning); your dataset is tiny (<500 rows, use logistic regression or a simple tree).
