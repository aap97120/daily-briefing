🧠 Data Science Topic of the Day

🎓 Bayesian Inference

Stop asking 'is this statistically significant?' — start asking 'what should I believe, and how strongly?'

What It Is

Bayesian inference is a framework for updating beliefs in light of new evidence. Instead of producing a single point estimate (e.g. 'the conversion rate is 4.2%'), it produces a full probability distribution over possible values — telling you not just what is most likely, but how uncertain you are. It is built on Bayes' Theorem: Posterior ∝ Likelihood × Prior. Your 'prior' encodes what you believed before seeing data; the 'likelihood' measures how well the data fits each hypothesis; the 'posterior' is your updated belief after combining both. This contrasts with frequentist statistics, which treats parameters as fixed unknowns and data as random — Bayesian statistics treats parameters as random variables with distributions, and data as fixed observations.

How It Works

1. DEFINE A PRIOR: Choose a probability distribution representing your belief about a parameter before seeing data. Priors can be 'informative' (based on domain knowledge — e.g. D&B Paydex scores cluster around 75–85 for healthy firms) or 'weakly informative' / 'non-informative' if you genuinely have no prior knowledge. Common choices: Beta distribution for probabilities, Normal for continuous values, Gamma for positive rates. 2. SPECIFY A LIKELIHOOD: Write down a statistical model for how the data was generated given the parameter. E.g. if modelling whether a firm pays on time, each observation is a Bernoulli trial with probability θ — giving a Binomial likelihood. 3. APPLY BAYES' THEOREM: Posterior = (Likelihood × Prior) / Evidence. The 'evidence' (marginal likelihood) is a normalising constant — often intractable analytically, which is why computation matters. 4. COMPUTE THE POSTERIOR — THREE APPROACHES: (a) Conjugate priors: In special cases (Beta-Binomial, Normal-Normal), the posterior has the same family as the prior — closed-form, instant. (b) Markov Chain Monte Carlo (MCMC): Algorithms like Hamiltonian Monte Carlo (Stan, PyMC) draw samples from the posterior when it cannot be computed analytically. (c) Variational Inference (VI): Approximate the posterior with a simpler distribution by minimising KL divergence — much faster than MCMC, used in large-scale models (e.g. TensorFlow Probability, Pyro). 5. READ THE POSTERIOR: Key summaries — posterior mean/median (point estimate), credible interval (e.g. 95% CI means 'there is a 95% probability the true value lies here' — fundamentally different from a frequentist confidence interval), and posterior predictive distribution (what new data will look like). 6. UPDATE SEQUENTIALLY: Yesterday's posterior becomes today's prior. This is Bayesian updating — ideal for streaming data where beliefs should evolve continuously rather than waiting for batch analysis.

When To Use

USE BAYESIAN INFERENCE WHEN: (1) You have small or sparse data and need to incorporate domain knowledge to avoid overconfident or nonsensical estimates — e.g. modelling default risk for a newly onboarded SME with only 3 months of payment history. (2) You need a full uncertainty distribution, not just a point estimate — e.g. forecasting revenue for a pipeline deal where you want P10/P50/P90 outcomes, not just an expected value. (3) You are doing sequential / online updating — new data arrives continuously (daily Paydex updates, real-time firmographic changes) and you want beliefs to update incrementally. (4) You need interpretable probabilistic statements for decision-makers — 'there is a 78% probability this account will churn within 90 days' is actionable; a p-value of 0.04 is not. (5) You are building hierarchical models — e.g. modelling conversion rates across 50 territories simultaneously, pooling information across them (partial pooling) to avoid both underfitting (grand mean) and overfitting (treat each territory independently). AVOID when: data is abundant and computation cost matters more than uncertainty quantification; or when a frequentist test is sufficient for a simple binary decision.

🎯 Worked Example — D&B Context

PROBLEM — PAYDEX SCORE DRIFT DETECTION ACROSS A CORPORATE FAMILY: D&B monitors payment behaviour for 600M+ businesses. For a given corporate family (say a mid-market manufacturer with 12 subsidiary entities), you want to detect early-warning deterioration in payment behaviour before it becomes a Paydex cliff-drop. NAIVE APPROACH: Flag when Paydex drops below a threshold (e.g. 70). This is reactive and noisy. BAYESIAN APPROACH: (1) Prior: For each subsidiary, initialise a Beta(α, β) prior on its 'probability of paying within terms.' Historical Paydex distributions across the parent's industry SIC code inform α and β — an informative prior. (2) Likelihood: Each month, the subsidiary either pays within terms (success) or does not (failure) across N trade lines. This is Binomial — conjugate to the Beta prior. (3) Posterior update: After each month's data, update α' = α + successes, β' = β + failures. The posterior is Beta(α', β'). This takes milliseconds — no MCMC needed. (4) Hierarchical layer: Across all 12 subsidiaries in the corporate family tree, add a hyperprior on (α, β) themselves — fit at the parent level. This implements partial pooling: a subsidiary with sparse data borrows strength from siblings. A new overseas entity with only 2 months of data does not get a wild estimate — it is pulled toward the family's base rate. (5) Output for the Prospecting Agent / Pipeline Risk Agent: Instead of 'Paydex = 68,' the agent receives: 'Posterior mean probability of paying within terms = 0.71, 95% credible interval [0.61, 0.80], probability of further deterioration next quarter = 0.34.' (6) Temporal updating (Buydex integration): As new trade line data arrives weekly, yesterday's posterior becomes today's prior — the model is always current without retraining. A sudden cluster of late payments shifts the posterior sharply even with few observations, because the likelihood overwhelms a weakly-held prior. BUSINESS OUTPUT: The Account Intelligence agent can surface 'payment behaviour confidence score' alongside Paydex — enabling a salesperson to distinguish 'Paydex 72, highly certain, stable trend' from 'Paydex 72, high uncertainty, deteriorating posterior' — two very different risk profiles that a point score alone cannot convey. This is D&B's Explainability First principle in action: the posterior distribution is the ground truth, not a black-box score.
